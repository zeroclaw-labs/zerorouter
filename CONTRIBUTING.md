# Contributing to ZeroRouter

Thanks for your interest. Technical conventions — build, test, risk tiers,
formatting, review gates — live in [`AGENTS.md`](AGENTS.md). This file covers
only licensing and the contributor agreement.

## Contributor License Agreement (CLA)

External contributions require a signed **Contributor License Agreement**
before they can be merged.

Why: the AGPL-3.0 grant from a contributor does not, by itself, give the
project the right to relicense that contribution. ZeroRouter intends to keep
open the option of relicensing under a more permissive license (for example,
Apache-2.0) in the future. A CLA that grants the project a broad, relicensable
copyright license is what preserves that option — without it, a later
relicense would require chasing down every past contributor. (A Developer
Certificate of Origin is **not** sufficient for this: a DCO certifies the right
to submit under the current license but grants no relicensing rights.)

> **Status:** the CLA text and signing flow (e.g. a CLA-assistant check on
> pull requests) are being finalized and should be reviewed by counsel before
> the project accepts its first external contribution. Until then, the
> repository is developed in-house. If you want to contribute, please open an
> issue first so we can get the CLA in place.

## Reporting security issues

Please do not open a public issue for security vulnerabilities. See
[`SECURITY.md`](SECURITY.md) for private disclosure (to be added before public
release).
